## 2. Quy trình Git bắt buộc cho mọi task

1. Kiểm tra checkout, `git status --short --branch`, thay đổi người khác và dependency của task trước.
2. Fetch `origin`; cập nhật `develop` bằng fast-forward khi checkout an toàn. Nếu có divergence hoặc thay đổi chưa commit, giữ nguyên dữ liệu và xử lý bằng checkout/worktree riêng, không reset hoặc tự stash công việc người khác.
3. **Tạo nhánh mới từ develop mới cập nhật trước khi sửa file.** Ghi tên nhánh và SHA baseline trong commentary và ticket evidence.
4. Chỉ sửa phạm vi task. Task phụ thuộc chưa merge thì chờ integration vào develop; không tiếp tục trên nhánh task trước hoặc âm thầm cherry-pick.
5. Kiểm tra diff, validation, commit và bàn giao. Khi có PR, base là develop; ghi rõ kết quả mock và real API riêng.
6. Task kế tiếp lặp lại từ bước 1, với nhánh mới. Sửa lỗi tiếp trong cùng task vẫn dùng nhánh của task đó.

Nhánh roadmap hiện tại: `docs/fe2-roadmap-20261009`, gốc develop `3426d70`. Các tên nhánh bên dưới là đề xuất; ngày dùng ngày thực tế bắt đầu task, thêm hậu tố nếu đã tồn tại. File [AGENTS.md](../../AGENTS.md) lưu quy tắc để những lượt làm việc sau đọc lại.

## 8. Definition of Done và validation cho từng task

Một task đạt DONE khi: scope/owner và baseline rõ; behavior có evidence đúng phạm vi; tests liên quan đạt; không hồi quy authority/versions/privacy; diff review được; docs/handoff cập nhật; commit và delivery status rõ. Merge status được ghi riêng, local commit không đồng nghĩa đã có trên develop.

| Loại thay đổi | Validation tối thiểu |
| --- | --- |
| Docs-only | Đọc lại nội dung, kiểm link/source/branch và git diff --check; không cần chạy app tests |
| Page/form/API state | Focused Vitest cases theo hành vi, pnpm typecheck, pnpm lint, pnpm build, git diff --check |
| Router/sidebar/shared guard/navigation | Validation trên + actor/route negatives + browser keyboard/back/deep link/responsive |
| Mutation/concurrency/result | Mock regression + real isolated API/browser acceptance với readback; nếu thiếu runtime, ghi FE_DONE_BE_PENDING |
| Gate toàn FE2 trước delivery | Full suite machine-readable có inventory đầy đủ và zero failures; browser/real evidence trong scope; không chạy lại vô hạn nếu không có thay đổi mới |

Errors theo endpoint thực: 400 field/schema; 401 session; 403/404 access; 409 reload/reconcile, không replay write; 422 chỉ khi contract có; 429 backoff phù hợp; 5xx giữ draft/retry an toàn. Không suy ra error code bằng cách parse English detail text.

Mẫu evidence mỗi task: `docs/fe2/evidence/<ticket>/README.md` ghi baseline, files, contract/decision version, cases, command/result, mock vs real, artifact links, outstanding dependencies và merge status. Chỉ lưu artifact cần review, không commit build output/screenshot dump hoặc dữ liệu nhạy cảm.

Rollback: mỗi task giữ diff nhỏ và commit review được; khi cần đảo đã tích hợp, dùng revert commit/PR theo dependency, không reset shared develop. Contract/DB changes nằm ngoài FE2; không giả định rollback FE hoàn tác dữ liệu đã publish.
