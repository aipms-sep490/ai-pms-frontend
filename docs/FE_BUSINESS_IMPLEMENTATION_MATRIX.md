## Backend contract backlog and FE unlock conditions

1. P1 requirements/history is now implemented against the merged contract. Run scoped 403/409 and repeated-submission browser/API/SQL evidence before changing it to `DONE`.
2. Versioned Project Period Policy, P3 discipline/evidence, reporting-cycle/project-action-item, and evaluation-scheme authoring/publishing are now FE work, not missing-API assumptions.
3. Task/milestone/report/meeting optimistic concurrency: FE đã nối GUID token ở mọi mutation và có test serialization; cần bật strict mode trên DB E2E và chạy hai writer.
4. Meeting decisions/action items: FE đã nối forms/read views; cần test API-mode 403/409/SQL. Legacy meeting routes remain supported; generic project action-items require a distinct FE surface.

Trong bảng sau, chỉ các điều kiện nghiệm thu là đề xuất. Policy/quota/history/layered evaluation đã có contract BE tại `3579529`; các hàng đó là tiêu chí để FE kết nối và kiểm thử, không phải yêu cầu tạo lại route.

## Runtime acceptance

### Evidence from current local API and SQL sample

- `VITE_DATA_MODE=api` was active at `localhost:5173` against Backend `localhost:5080`. Browser journeys authenticated a Student leader, Student member, Lecturer and Department account. The Student ACTIVE Project, Lecturer supervisor assignment, and Department portfolio of 3 projects loaded from the API. The supplied test account document did not identify an Admin account.
- After the 2026-09-27 Design C update, the assigned Supervisor loaded Project 2 with 4 deliverable definitions, 6 progress reports and 9 meetings from the live API. The three list pages had no document-level horizontal overflow at a 390 px viewport. This is read/runtime evidence only; no mutation was sent to the shared demo data.
- Direct API checks verified `403` for Student/Lecturer requests to the Department dashboard; the Student member could read their final checklist but the Backend returned `LEADER_REQUIRED`. The Department could read the Project and evaluator assignments but could not read its Team. The evaluator page now uses scoped period reads and has a regression test for that boundary.
- The Department result preview returned blockers for final submission, locked package and result policy. The sample SQL has no EVALUATION period; its FINAL_SUBMISSION period is UPCOMING. No final submission, evaluation, result publication or archive mutation was accepted as complete.
- A 390 px browser viewport showed no horizontal document overflow on the rubric and evaluator pages. The current connected SQL data is reference/demo data rather than a proven isolated test database; the local Docker daemon was unavailable when checked. No E2E write-persistence or concurrent-writer claim is made from these reads.
- Read-only audit of the database supplied on 2026-09-27 found 76 application tables, 11 Student, 4 Lecturer, 2 Department Staff and 2 Administrator accounts by persisted role. It has one ACTIVE project with execution data, but no INTERDISCIPLINARY configuration, final submission, project result or optimistic token on task/milestone/report/meeting records. See the canonical BE/DB remediation audit in `../../ai-pms-backend/docs/BE_DB_REMEDIATION_AUDIT_2026-09-28.md`.
