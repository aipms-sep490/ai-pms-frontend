## Backend contract backlog and FE unlock conditions

1. Versioned Project Period Window/Policy: expose the active policy/window version and immutable snapshot rules; FE can then show exact configuration and stale-state handling.
2. Project quota/responsibility mutation: expose read/write DTO, scope authorization and concurrency token; FE can enable the editor after 403/409/SQL tests.
3. Historical registration snapshots/department decisions: expose scoped paged history; FE can replace the explicit history boundary without inferring old decisions from project status.
4. Task/milestone optimistic concurrency: expose version/token and return 409 on stale writes; FE can submit the token and refresh without replay.
5. Meeting decisions/action items, layered evaluation and StudentResult: define ownership, lifecycle, immutable evidence and publication rules; FE adds forms/read views only after those contracts are deployed.

The following routes and DTO names are **proposed BE contracts**, not deployed endpoints. FE must not call them until OpenAPI, authorization tests and SQL persistence match.
