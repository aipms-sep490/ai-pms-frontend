# AI PMS frontend gap implementation plan

## Scope and authority

Snapshot: 2026-09-27. This is a contract-first frontend plan for `feature/project-workspace-ui-20260926`. Business documentation is the business authority; the current backend controllers and DTOs are the executable API authority. React provides route and interaction guards only. It must not calculate project state, scoped authorization, eligibility, capacity, grades, publication, or automatic contribution grades.

Global identity roles are `ADMIN`, `DEPARTMENT_STAFF`, `LECTURER`, and `STUDENT`. Student leader/member, primary supervisor, and evaluator are contextual authorities that must come from current team membership or active backend assignment on the relevant project.

The requested filenames with SRS `(5)` and SDD `(3)` suffixes were not present. This audit used the available `AI-PMS - Report 3 - Software Requirement Specification.docx` and `AI-PMS - Report 4 - Software Design Document .docx`, together with the other five named documents.

## Cross-cutting implementation rules

- Guard direct routes with authenticated session, backend-derived workflow/project state, and scoped resource reads. A failed API response remains authoritative.
- Show loading, empty, 400, 401, 403, 404, 409, and unexpected-error states. On 409, reload authoritative state and require a new human action; never replay the mutation.
- Reuse `src/services/http/http-client.ts` and the existing authentication refresh bridge. Do not add a second HTTP client or production fixtures.
- Treat AI and contribution as advisory. `INSUFFICIENT_DATA` is a visible state, not low risk or a grade.
- Keep `ARCHIVED` surfaces read-only. Do not expose a write action based on client state alone.

## Confirmed backend gaps and exclusions

Do not add frontend contracts for Team Working Agreement, structured discipline responsibility, project functional roles, task discipline, semantic evidence ledger, discipline mentor, checkpoints/review gates, EvaluationScheme, full `COMMON`/`MAJOR_SPECIFIC`/`INDIVIDUAL` scope, `StudentResult`, AI supervisor ranking, persistent AI conversation history, notification preferences, or an industry-partner portal unless the deployed backend contract is re-audited first.

The Governance Baseline identifies multi-scope evaluation and per-student results as gaps. Therefore the evaluator UI may use only the currently deployed assignment DTO; it must not create client-only scope selectors or calculate scores/results.

## Phase exit criteria

For every phase: connected API in API mode, navigation where appropriate, backend-derived RBAC and state guard, all required error/empty/loading/conflict states, focused tests plus `pnpm lint`, `pnpm test`, `pnpm build`, and `git diff --check`. A feature is `DONE` only after browser/API and persistence evidence demonstrate the authorized lifecycle.
